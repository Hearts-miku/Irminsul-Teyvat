# 世界树-提瓦特 · Irminsul-Teyvat

提瓦特的风吹过七国，也将无数未曾说尽的故事，留在世界树的枝叶之间。

**世界树-提瓦特（Irminsul-Teyvat）**，是一座献给旅行者的同人记忆书库。在这里，风语精灵会陪你翻阅旅途中的片段：重逢熟悉的人，追寻某个名字背后的往事，或拾起一段被遗忘的对话，让散落的线索慢慢连成故事。

你不必一次知晓所有秘密。告诉它你走到了哪里，再从一句“后来呢”开始，让那些走过的路、遇见的人，在交谈中重新鲜活起来。

## 启动

从 GitHub 克隆源码后，安装 Node.js 24，再执行：

```sh
git clone https://github.com/Hearts-miku/Irminsul-Teyvat.git
cd Irminsul-Teyvat
npm ci
npm start
```

`npm run web` 启动浏览器版本；`npm test` 运行程序测试；Windows 下 `npm run pack` 生成桌面运行目录。仓库附带本地语料及本体索引，普通构建不需要重新采集 Wiki，也不需要模型密钥。若要重建索引或更新来源，请参阅 `docs/CORPUS-IMPORT.md` 和 `docs/ONTOLOGY-FULL.md`。

依赖、打包产物、下载缓存、测试运行记录、用户会话及本地密钥均不提交到仓库。

双击项目根目录的 `START.cmd`。如果已经打包，会直接启动 `release/win-unpacked/Irminsul-Teyvat.exe`；没有打包时，会使用本机 Node.js 构建并启动。

如果拿到的是独立运行包，直接双击同目录的 `Irminsul-Teyvat.exe`。运行目录需要可写，用于保存 `user-data`。

分发时请复制整个 `release/win-unpacked` 目录。打包版包含运行环境，不需要单独安装 Node.js。不要只复制其中的 exe。

桌宠可以拖动；点击精灵直接展开小对话面板，可以输入问题、连续追问、查看出处和停止讲解。面板与主窗口共用当前会话、剧情范围及模型配置；点击右上角箭头打开完整窗口，减号或 Esc 收起面板。关闭主窗口会收起为桌宠，托盘菜单提供退出功能。快捷键为 `Ctrl + Shift + Space`，如果被其他程序占用，仍可从桌宠或托盘打开。

## 第一次使用

1. 在「模型与偏好」选择「在线模型讲解」。
2. 填写服务商提供的 **Chat Completions 兼容地址**（通常以 `/v1` 结尾）、模型 ID 和 API Key。
3. 点击「保存并测试连接」。请求地址会补全为 `/chat/completions`；已经填写完整端点则不重复追加。
4. 打开「剧情目录」，搜索任务或人物，也可展开「直接选择讲解主题」。选中关联提纲或摘要、确认范围后，会新建对话并保留旧对话。
5. 点击建议问题或输入自己的问题。点击回答中的出处编号，查看摘要或提纲、剧情位置及来源；固定修订号只在取得时提供。
6. 想查后续剧情时，切换到「原文资料库」，按任务、系列或人物搜索；勾选「同时搜索正文」可查对白关键词。选择某页后，问题与追问只使用该页匹配片段。系列入口若没有正文，请选择其具体子任务。

在线模式会将当前问题、必要的近期问题和本轮检索资料发送给所配置的模型服务。连接测试会发出一次简短模型请求。

Windows 桌面版使用 Electron safeStorage 的系统加密保存密钥，界面不回显。更换服务地址必须重新填写密钥，防止旧服务的密钥被自动转发。支持 HTTPS 服务和本机 HTTP 服务。

如果暂时没有配置模型，可选择「资料讲解」，离线检索并组合已整理的资料。该模式不是大模型生成。在线请求失败、超时或回答未通过引用检查时，界面会明确提示并回退到资料整理。

## 剧情内容

程序读取 `data/program-content.json` 与 `data/catalog/program-index.json`。构建时自动从三份提纲、原目录快照、原蒙德片段、`data/story-expansion.json` 、`data/mondstadt-story.json` 、`data/liyue-story.json` 与 `data/journey-bridge-story.json` 生成；无需联网或模型密钥。

原文资料独立保存在 `data/corpus/pages.json`；使用 `npm run corpus:build` 从已采集缓存重建。日常 `npm run build` 和已打包程序直接使用该文件，不需要缓存或联网。原文使用独立 `source` 类型，不进入精选摘要的核对状态或数量。

- 目录：3,472 条出现记录，包含 51 条主线入口、840 条世界任务/探索入口、2,139 条 NPC 名录记录等。数量不是独立任务或人物总数。
- 提纲：30 个主题、185 条资料，覆盖主线、世界任务和 NPC 对话规划。界面和模型均明确标为提纲，待核对情节不能据此补写。
- 精选剧情：原有 14 条、v0.2 补充 18 条、v0.3 蒙德三幕新增 45 条、v0.4 璃月三幕新增 36 条，v0.5 旅人线与稻妻序幕新增 33 条，共 146 条。首批补充来自提米的信、阿芬迪招募、森林书初遇拉娜、葛罗丽的思念、刘苏说书和卡嘉日常对话。每个新主题有明确的内容边界和来源。蒙德三幕已增加可问答的故事脉络与人物动机摘要，见 [蒙德内容说明](docs/MONDSTADT-CONTENT.md)；璃月前三幕新增任务动机、市井与 NPC 对话摘要，见 [璃月内容说明](docs/LIYUE-CONTENT.md)。
- 所有新增主题使用独立范围，选择较大编号不等于解锁其他主题。提纲导览可能包含其所列章节的后续线索；选择前会展示范围说明。

内容包 `data/mondstadt-prologue.json` 覆盖三个连续任务的精选资料：

1. 随风而来的骑士：初遇、盘问、护送、派蒙介绍的互斥选项、寻找家人。
2. 与轻风同行：城外工作、并肩作战与局势解释。
3. 自由之都：进城、琴的身份介绍与谢礼。

原始部分包含 **14 条资料记录、3 个任务、3 个固定版本来源页**。所有精选资料均为自行组织的整理，原始包另含少量原文短摘，**不是全量原文、完整序章，也不是全游戏正文数据库**。来源与许可见 `docs/SOURCES.md`。

新会话默认只开放第一段。通过「调整剧情进度」主动扩大范围。改变范围会清空当前会话的消息和上下文，其他会话保留。档案和出处接口也执行同一边界检查。人物被提及本身不会解锁后续剧情。

建议验证：

- 安柏为什么怀疑旅行者？ → 那她为什么还要护送我们？
- 派蒙真的是应急食品吗？ → 展开分支出处。
- 第一段进度下询问风之翼 → 应提示超出范围。
- 开放第三段后询问安柏为什么赠送风之翼 → 应给出依据。
- 安柏的生日是哪天？ → 应说明资料未收录。
- 安柏的技能倍率是多少？ → 引导到资料图鉴占位。

「导出手记」可以将当前对话与出处保存为 Markdown。

## 实际实现架构

- 桌面：Electron，独立聊天窗口与透明桌宠窗口、托盘、快捷键、限制范围的 IPC。
- 界面：Vue 3 + TypeScript + Vite；本地打包静态资源，无远程字体或图片依赖。
- 本地服务：Node.js HTTP 服务，只监听 `127.0.0.1`；应用令牌、Host/Origin 校验和 CSP。
- 数据：Node.js 内置 SQLite，持久化剧情记录、会话与非敏感偏好；内容包导入时记录 SHA-256。
- 检索：中文分词、双字词与 BM25 类关键词排序，叠加任务范围和会话主题。验证版没有向量数据库或语义嵌入。
- 模型：Chat Completions 兼容 HTTP 接口，服务端持有凭据。模型输出结构化段落与资料 ID。
- 回答：校验 JSON 结构、引用白名单及部分越界词后，通过 SSE 分段推送。**为了先检查内容，在线模型请求本身使用非流式返回；前端接收的是校验后的分段推送，并非模型原生 token 流。**

此前设计建议的 Python/FastAPI 本地服务，在本次验证实现中调整为 Node.js，以复用本机及 Electron 运行环境。业务服务仍与界面分开，便于后续替换。

## 数据保存位置

| 运行方式 | 数据目录 | 密钥 |
| --- | --- | --- |
| 源码桌面版 | `.local/desktop` | `model-key.enc`，系统加密 |
| 打包桌面版 | exe 同目录的 `user-data` | `model-key.enc`，系统加密 |
| 浏览器验证 | `.local/browser` | 仅进程内存；服务退出后需重新填写 |

目录中的 `stories.sqlite` 保存会话、进度与偏好。源码、浏览器、打包版本的数据目录独立。系统加密文件不保证能在另一个 Windows 账号下解密；迁移时重新填写密钥。

## 开发与测试

源码开发需要 Node.js 24 或更新的兼容版本。TypeScript 固定在与当前 Vue 检查器兼容的 5.9.3。

```powershell
npm ci
npm run build
npm start
```

浏览器验证：

```powershell
npm run web
```

打开 `http://127.0.0.1:4210`。浏览器版不创建操作系统桌宠；桌宠须用 Electron 版验证。

```powershell
npm test
npm run test:ui
npm run test:catalog-ui
npm run test:mondstadt-ui
npm run test:liyue-ui
npm run test:bridge-ui
npm run test:desktop
npm run pack
```

浏览器检查优先使用本机 Edge 或 Chrome；无浏览器时可通过 Playwright 安装 Chromium。测试结果和截图在 `test-results`。在线协议测试使用本机模拟服务与明显的测试占位密钥，**不代表已验证用户的真实模型账号**。

## 当前限制

- 自由问题的召回依赖小规模资料的词汇覆盖，复杂指代与跨场景推理仍可能漏检。
- 旧剧情目录的摘要关联仍有限，原文资料在独立的「原文资料库」中检索。旧 NPC 地区索引的归属信息仍有缺口；这与当前原文采集清单已补齐是不同的统计。新章节实装状态仍需核对。
- 引用白名单和越界词检查不能证明每一句模型回答都被证据完整支持，也不能保证识别所有改写形式的剧透；界面保留原文核对入口。
- 本期没有语音、Live2D、全量剧情导入、版本自动更新和效果图鉴数据。
- 模型凭据仍需用户在本机填写后验证真实服务；没有预置任何真实密钥。

首期范围设计在 `docs/story-first-plan.md`，实际验证记录在 `docs/VALIDATION.md`。


## 自动补充内容的工具

已接通 BWIKI 公开只读 API。使用 `npm run content:collect -- journey-bridge` 批量采集，`npm run content:prepare -- journey-bridge` 生成待核对场景清单，整理后运行 `npm run content:audit` 构建并检查来源变化。无需在线模型密钥；采集不会自动发布未核对内容。具体流程、缓存与分支处理见 [自动化说明](docs/CONTENT-AUTOMATION.md)。
