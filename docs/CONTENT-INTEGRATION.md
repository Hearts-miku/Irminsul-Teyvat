## 数据生成

`npm run content:build` / `npm run build` 执行 `scripts/build-program-content.mjs`，读取：

- `data/catalog/index-snapshot.json`：先前的公开目录快照，不再次爬取网站。
- `docs/story-outline/MAIN-STORY.md`、`WORLD-STORY.md`、`NPC-DIALOGUE.md`：本地整理提纲。
- `data/mondstadt-prologue.json`：原验证片段。
- `data/story-expansion.json`：新增的来源摘要。

生成 `data/program-content.json`（讲解资料）和 `data/catalog/program-index.json`（目录）。`contentType` 区分 `outline` 与 `summary`；`scopeMode: independent` 表示仅当前主题。提纲来源包括本地文档、章节名、外部参考链接。提纲记录以正文哈希标识，避免插入段落后旧编号指向另一条内容。

目录的 `guideIds` 按规范化名称在提纲中定位，仅表示相关导航；`summaryIds` 来自人工维护的名称映射。对同名 NPC 不自动合并。原目录的 `dialogueStatus` 继续为 `pending`。

`/api/catalog` 支持 `q/kind/region/availability/page`，每页 40 条。`/api/catalog/:id` 提供来源详情。和其他接口一样，必须带本地应用令牌。

## 范围与升级

原蒙德 1–3 段保持累计解锁。新增主题只检索自身资料。目录启动主题会创建新会话；同一会话中调整范围仍清空该会话上下文。旧 SQLite 聊天、进度、偏好及加密密钥保存方式兼容，不需要删除数据。

目录可完整浏览，正文只有所选范围参与回答。主题内的摘要不承诺逐句进度控制。模型仅获得本轮检索资料，输出需通过引用与结构检查；这不能证明每句话都无误，仍可回查来源。

## 仍待补充

主线可按提纲导览，但大部分幕还没有逐场剧情正文。世界任务、传说、活动、邀约和大多数 NPC 仍需逐页补充证据及分支条件。部分 NPC 地区页读取失败、新版本实装状态未独立核实，继续沿用原覆盖报告的缺口标记，不以目录记录数充当对白完成率。
