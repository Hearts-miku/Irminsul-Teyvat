## 明确未完成的范围

| 缺口 | 影响 | 后续补全方法 |
| --- | --- | --- |
| NPC 须弥、挪德卡莱、至冬地区页读取失败 | 对应地区名录不完整；即使其他页包含部分人物也不能算补齐 | 从可用人物页、任务出场表和可访问数据源补齐，再与地区索引对账 |
| 活动任务总表读取失败 | 目前以传说页的 42 个活动系列入口兜底，短活动易遗漏 | 按版本历史逐版本核对活动与全部阶段驻场对话 |
| 任务分类页 / NPC 分类后续分页未取得 | 未能用分类全量枚举校验主目录遗漏 | 后续恢复访问后检查全部分页并比较差集 |
| 新版本目录与旧缓存不一致 | 同一次整理无法证明所有页面处于同一游戏版本 | 查官方更新公告，单独保存版本号与来源获取日期 |
| 魔神/传说/部族系列未完全展开 | 有幕级入口，没有完整子任务和场景树 | 逐系列展开子任务，并核对与前置任务的连接 |
| 邀约与游逸旅闻仅角色入口 | 不知道完整幕数、事件数和结局数 | 逐角色展开，保留全部路线、失败与重复条件 |
| NPC 全部对白未采集 | 名录不能用于生成具体台词或断言其完整经历 | 逐人核对日常、任务、委托、活动和不同世界状态 |
| 书籍、物品故事、邮件和环境文本未做全目录 | 可能缺少支线解释所需证据 | 按证据类型建立独立索引，与已定位任务关联 |
| 尚未与游戏原始任务/人物 ID 对账 | 无法可靠合并别名、同名、跨页重复 | 用合规可用的数据快照或游戏内记录建立映射 |

因此这份交付应称为**广覆盖剧情提纲与候选索引**，不能称为“已收录全部剧情和 NPC 对话”。

## 后续入库的验收单位

每个条目至少经历五个独立状态：索引找到 → 原文取得 → 结构解析 → 人工核对 → 可用于讲解。当前目录默认停在第一步。

- 主线：按章节核对幕、子任务、场景、可选谈话和结尾 NPC；全量目标以版本清单为分母。
- 世界任务：系列、单任务、隐藏事件分别计数，不能用含父子重复的目录条数算百分比。
- NPC：人物身份、出现状态、对话入口、分支节点分别计数；取得姓名不算取得对白。
- 活动：按版本和阶段检查主线、支线与驻场；活动结束不等于内容不重要。
- 每批保存缺失项、未解析占位符、断开的分支、没有出处的摘要，不以“待补”文本充当原文。

## 数据与文件

`data/catalog/index-snapshot.json` 是本次结构化目录的源文件，含来源、页面修订号、标题、类型、位置、索引行定位和待核对状态。

`sourceLine` 是本轮网页读取器中的行位置，仅用于追踪采集依据，**不是原始对白 ID 或 Wiki 源代码行号**。检索链接按显示标题生成；为了避免同名歧义，不冒充已验证的子页面永久链接。

从已保存的元数据重新生成分类文档和离线页面：

```powershell
node scripts/build-story-catalog.mjs
```

此命令不联网、不需要模型密钥，也不修改桌宠内容包。`--extract` 是仅针对本轮本地采集缓存的提取模式；其中世界任务地区分界锁定修订号，来源变化后必须人工复核。该提取器不是已完成的通用全量爬虫。

## 文件验证

执行 `node scripts/verify-story-catalog.mjs`，9 项检查通过：ID 与来源关联、元数据哈希、文档交叉链接、离线打开、类型筛选、关键词检索与出处、JSON 导出、空结果/分页、窄屏显示与脚本错误检查。报告保存在 `test-results/story-catalog-report.json`，截图以 `story-catalog-` 开头。

这些检查证明目录和阅读工具可用，不证明全量剧情、逐句对白或所有推断已经核实。
