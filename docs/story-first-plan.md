# 原神剧情互动内容库：首期范围与架构

更新日期：2026-09-29

本文保留产品范围与原始建议架构。2026-09-29 已开始按此范围开发验证版；实际实现、启动方式与当前限制以根目录 README.md 和 docs/VALIDATION.md 为准。验证版将本地服务调整为 Node.js，以复用桌面运行环境。

## 1. 本次确定的产品范围

- 首期专注于剧情方面的互动，桌宠作为剧情讲解与追问的入口。
- 角色、武器、圣遗物的效果说明，后续通过固定页面呈现；本期仅预留入口与占位页。
- 角色的背景、关系与经历，以及武器、圣遗物中的故事文本，仍属于剧情资料范围。
- 初期默认提供有出处的剧情讲解；剧情分支模拟、原创续写与沉浸式角色扮演不属于当前默认范围。

## 2. 交互与页面

### 剧情桌宠

点击桌宠或使用快捷键打开对话窗口，支持：

1. 回顾事件：解释某段任务发生了什么。
2. 解释人物：结合已知对话与故事说明人物行为、关系和动机。
3. 连续追问：解析“她”“那件事”“后来”等上下文指代。
4. 调整讲解：简要回答、详细讲解、查看原文出处。
5. 控制剧透：按用户提供的已完成任务或已确认剧情范围限制内容。

桌宠动画使用待机、检索、讲解、等待输入等状态。长回答、原文和引用放在独立对话窗口中，保持桌宠本体简洁。

回答建议包含：直接回答、必要的前因后果、出处。涉及动机分析时，清楚区分原文明示与推断。用户输入可以建立对话上下文，但不直接成为剧情事实。

### 固定页面占位

- 建议入口名称：资料图鉴。
- 建议路由：`/reference`。
- 页面说明：角色、武器、圣遗物的效果说明将在这里呈现，正在规划中。
- 页面只展示三类占位卡片，不填充模拟数值或未实现的查询功能。
- 当桌宠收到纯效果或数值问题时，引导至该入口并说明内容尚未上线。
- 混合问题先回答有依据的剧情部分，效果部分提示后续由资料页提供。

这里预留的是产品页面，不要求将资料图鉴实现为独立网站或单独部署的服务。

## 3. 建议架构

```text
桌宠窗口 + 对话窗口                 资料图鉴固定页
          |                         （本期占位）
          v
剧情问答服务
  - 会话与指代解析
  - 用户剧情进度与剧透范围
  - 人物、地点、事件、任务名称识别
          |
          v
检索原文与相关上下文
  - 关键词检索 + 语义检索
  - 场景及任务关系补全
  - 对全部证据执行版本与剧透过滤
          |
          v
证据整理 -> 模型讲解 -> 出处与范围检查 -> 流式回答

数据导入程序 -> 原始快照 -> 规范化剧情库 -> 摘要与检索索引
```

建议沿用 Electron + Vue 的桌面层、Python + FastAPI 的本地服务和 SQLite 基础存储。向量索引、生成模型采用可替换接口；具体依赖版本在实现前确定。

数据加工独立于问答运行：问答读取已校验的内容版本，不在每次提问时临时抓取全网内容。内容与会话在本地保存；如果选择在线生成模型，回答所需的问题和证据片段会发送给模型服务。完全离线需额外部署本地模型。

## 4. 剧情数据组织

| 数据对象 | 需要保留的信息 |
| --- | --- |
| 来源快照 | 来源、提交号或页面版本、获取时间、对应游戏版本、覆盖范围 |
| 人物与地点 | 内部 ID、来源 ID、名称、别名、关联任务；包含 NPC |
| 任务与场景 | 章节、任务类型、前置关系、场景位置、分支条件 |
| 对话节点 | 说话人、原始文本、规范化文本、前后节点、选项分支、原始定位 |
| 其他剧情文本 | 角色故事、书籍、物品故事、世界观文本及解锁条件 |
| 摘要 | 任务或场景摘要、关联原文 ID、生成所用的数据版本 |
| 用户进度 | 已完成或已确认知晓的任务、允许涉及的内容范围 |
| 对话会话 | 当前讨论对象、最近问题、明确确认的用户偏好 |

任务先后关系与世界观事件发生时间分别记录。文本 ID 不作为剧情时间排序依据；不确定的事件时间保持未知。

角色台词可能表达个人判断、不完整认知或谎言，不能直接当作全知事实。保留说话人、场景和叙述来源，供讲解时判断证据含义。

## 5. 检索与讲解规则

- 先按任务、场景定位，再检索原文；需要概括大段剧情时，先找章节或场景摘要，再回查原文。
- 保留对话分支，不把互斥选项串接成同一段已发生的剧情。
- 对旅行者名字、性别、可变角色名称等占位内容保留原文，并生成规范化展示文本。
- 剧透控制在检索和关联上下文补全时执行，输出前再检查；不能只依赖提示词。
- 摘要继承其引用材料的剧透限制，避免摘要暴露尚未开放的剧情。
- 首次使用时允许用户设置已完成任务；未设置时默认限于本轮指定任务，不自动扩展到后续内容。
- 仅有用户主动提及某个人物，不代表允许讲解其全部后续经历。
- 缺少证据或来源冲突时说明缺口；推测与原文明示分开呈现。
- 回答中的出处关联本地原文位置与可用的来源链接，便于用户展开核对。

## 7. 首个可验证版本

1. 选择一段任务边界清楚的剧情，建立固定来源快照与覆盖清单。
2. 完成说话人、场景、顺序、分支和原文定位的人工抽查。
3. 实现该范围内的问答、追问、出处展开和剧透控制。
4. 接入桌宠与对话窗口；同时实现资料图鉴占位页。
5. 验证具体台词查询、事件概括、人物动机分析、代词追问、分支混淆、越界剧透和证据不足等问题。

通过这一闭环后，再扩大剧情覆盖。语音、复杂动画、全量世界观关系图与效果图鉴作为后续工作。
