## 自动化过程

```powershell
# 默认续传：验证缓存哈希，跳过成功页面；每批最多 50 页，批次间至少 15 秒
npm run corpus:collect

# 只从本地缓存构建原文资料库，并输出完整覆盖和缺口报告
npm run corpus:build
npm run build
npm test
npm run test:corpus-ui

# 主动重枚举分类并更新源页面；不会读取在线模型密钥
npm run corpus:collect -- --refresh
```

采集仅使用公开 MediaWiki 只读接口，无账号和密钥；运行前核对 robots.txt。遇到 HTTP 服务拒绝或限流即停止，保留已经成功的页面，不换代理、不绕过验证。任务页与 NPC 页交错续传。支持从 `pageid` 固定页面身份，记录修订号、采集时间和源码 SHA-256。已获取的页面不因后续失败而被删掉。

本轮有一页 NPC 资料从前期同一公开 API 的已验证探测缓存恢复，哈希与修订信息同样保留。采集报告反映各次尝试；构建报告反映实际可用缓存总量。

## 来源与解释边界

- 公开来源：[原神 BWIKI](https://wiki.biligame.com/ys/)。页面标注 CC BY-NC-SA 4.0；社区编辑文字按该声明保留署名、来源与许可信息，游戏原始内容权利归原权利人。本项目的解析转换不改变原内容归属。
- 原始 wikitext 留在 `.cache/corpus/pages/`，程序携带 `data/corpus/pages.json` 的正文解析结果、出处和状态。程序不执行来源 HTML、脚本或 Wiki 模板。
- 解析器保留场景标题、NPC 对话阶段以及嵌套选项路径；不支持的模板显示标记或参数，未模拟服务端条件求值。页面有对白标记不等于对白完整；片段编号也不是游戏对白 ID。
- 原文页可包含整页后续线索，用户选择范围时会看到说明。会话只检索所选页；早期精选主题不会自动获取其他页的证据。系列总页仅有索引时，需通过系列名称选择具体子任务。
- 原文和精选摘要分开计数。自动采集日期不作为人工核对日期；不会自动把 `source` 变成 `summary` 或 `reviewed`。
- 在线模型只得到匹配片段并必须引用本次资料 ID。资料不足时不补写；不能把互斥选项、人物观点或未展开模板当成已确定事实。尚未验证用户真实的模型服务，本轮使用本地模拟服务测试协议。

串行、分组与缓存策略参考 [MediaWiki API 使用建议](https://www.mediawiki.org/wiki/API:Etiquette)。现有逐页 HTML 采集和人工摘要核对流程仍可使用，见 [剧情自动化入库](CONTENT-AUTOMATION.md)。
